# Fixes — November 2026 audit

Backend suite: **197 passed** (was 187 passed / 4 failed). Plugin suites: omniwa-assist 16 passed, omniwa-group-privacy 8 passed.
Checked against the current upstream Hermes Agent source (NousResearch/hermes-agent, Nov 2026), which `nousresearch/hermes-agent:latest` pulls.

## Breaks things at runtime

1. **Allowlisted groups were silently dropped.** Hermes gates groups (`group_policy: allowlist`) on `group_allow_from` (`WHATSAPP_GROUP_ALLOWED_USERS`), not `allow_from`. The dashboard put group JIDs in `allow_from`, so the bridge logged `group_policy_rejected` for every group.
   Fix: `bridge_config_service` now also writes the `@g.us` entries to `group_allow_from`. The dashboard still shows one list.
   *After deploying, open the Connection Mode card and press Apply once so the file is rewritten.*

2. **"Generate New QR" re-pairing could never work.** The same volume is mounted at `/opt/hermes_data` in the backend and at `/opt/data` in hermes.
   - The `docker exec` command ran inside hermes but wrote the QR log to `/opt/hermes_data/...`, a path that doesn't exist there.
   - The "repair" symlink was absolute to the backend path, so it dangled inside hermes. That caused the same wizard crash the code was meant to fix (a repair loop).
   Fix: the symlink target is now relative, and the command uses `HERMES_CONTAINER_DATA_DIR` (default `/opt/data`).

3. **The group assistant could not accept its own offers.** The bot answers a keyword with "shall I…?", but the member's plain "yes" had no keyword and no @mention, so it was skipped.
   Fix: for 5 minutes after an offer, that member's next message in that chat passes through. It's one-shot.

4. **Keyword false positives.** Substring matching fired on facebook/notebook (book), border (order), and explanation/planet (plan).
   Fix: keywords now match whole words only.

5. **Mentions missed.** `@bot:12@lid` device-qualified ids, typed `@number` mentions and `/commands` were treated as chatter.
   Fix: these now follow the same rules as the Hermes adapter.

6. **Contact allowlisting wrote unusable entries.** The gateway reports senders as `919…@s.whatsapp.net` or `…@lid`, so allowlisting produced `919…@s.whatsapp.net@s.whatsapp.net`.
   Fix: identities are normalized on ingest and on allowlist, and LIDs are kept exact.

7. **Permissions page 403 "Owner not found"** whenever `OWNER_WA_PHONE` was unset or formatted differently, even when an owner row existed.
   Fix: it now falls back to the `is_owner` row.

## Security loopholes

8. **`/connect-google` was public.** Anyone with the URL (it's in SOUL.md) could link their own Google account. The callback overwrote the owner's tokens, synced them into Hermes and restarted the agent.
   Fix: the route now requires a dashboard session. Unauthenticated visitors go to `/login?next=/connect-google`. Login honours a safe `next`, so open redirects are blocked.

9. **The default `ADMIN_PASSWORD=admin123` opened the dashboard** whenever no dashboard users existed. Any DB error also fell through to the legacy login.
   Fix: the default or any password under 8 characters is refused, the comparison is constant-time, and unexpected DB errors fail closed.

10. **Cross-tenant contact allowlisting.** A user could allowlist another tenant's contact by id.
    Fix: the contact's tenant is now checked.

11. **Group privacy plugin.** It now also turns on when the session's `chat_type` is `group`, not only when the chat id ends in `@g.us`.

## Deployment

- `scripts/deploy_hermes_plugins.sh` copies SOUL + both plugins, **enables** them, runs their tests in-container and restarts. Current Hermes treats user plugins as opt-in, so a copied-but-not-enabled plugin is silently ignored.
- omniwa-assist only sees non-mention group traffic when `require_mention` is off. With it on, the adapter drops those messages before any plugin runs.

## Not changed (recommendations)

- `docker-compose.yml` uses `nousresearch/hermes-agent:latest`. Pin a tag that you've tested so upstream changes (like #1) can't break you overnight.
- `backend/hermes_config.yaml`, `scripts/setup.sh` (requires Ollama) and the LiteLLM rebuild on startup are left over from v2 and are dead. Delete them or mark them legacy.
- Inbound per-sender rate limiting is still not enforced (already listed in CONTEXT.md).
- The opencode-zen 401s in CONTEXT.md are external. Regenerate that key, or replies stay slow through the fallback chain.
